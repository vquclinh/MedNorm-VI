## 3. Title Recovery (§4)

`src/mednorm_vi/kb/icd10/repair/title_recovery.py`. Damage predicate: the name is an ICD
instruction (`Bao gồm` / `Loại trừ` / `Incl.` / `Excl.` / `Lưu ý` / `Tham khảo`), ends
mid-phrase (`,` `:` `(` `-` `+` `/`), or is ≤ 6 characters. Clean titles are never rewritten.

| | Count | Share |
| --- | ---: | ---: |
| Concepts | 15,308 | |
| **Damaged titles (v3)** | **2,777** | **18.1%** |
| **Recovered from governed source** | **673** | 24.2% of damaged |
| Still damaged (v4) | 2,104 | 13.7% of index |

### A correctness defect found and fixed mid-implementation

The first anchor matched the code token anywhere in a row. A category code such as `B05`
also appears in every one of its subcodes' rows, so B05 recovered **B05.9's** title
(`Bệnh sởi không biến chứng`) and A06 recovered **A06.6's**. Recall looked better — 41.2% —
and the titles were wrong. A wrong title is worse than a damaged one: it makes a concept
confidently reachable by the wrong name.

The anchor now requires the adjacent `<dotted code> <undotted code>` pair that uniquely
identifies a concept's own row, with a bounded fallback for a `pdftotext` layout artifact
that glues the dotted column onto wrapped text. Recall fell to 24.2% and precision became
the property that matters. Spot-checked recoveries: `B05 → Bệnh sởi`,
`C15 → U ác tính ở thực quản`, `M10 → Gút [thống phong]`, `G10 → Bệnh Huntington`,
`C20 → U ác tính ở trực tràng`.

The 2,104 unrecovered records are mostly cases where the title wraps across `pdftotext`
lines and the column is truncated at the layout boundary. They remain damaged rather than
being guessed.

## 4. Governed Alias Layer (§5)

`src/mednorm_vi/kb/icd10/repair/alias_layer.py`. v3 had **0** populated alias lists across
15,308 concepts; RxNorm had 82,429. That absence is why *ung thư tụy* could not reach C25,
stored as *u ác tính ở tụy* — the same disease in a different clinical register.

| Alias type | Count |
| --- | ---: |
| `canonical_title` | 13,204 |
| `unaccented_variant` | 14,779 |
| `punctuation_variant` | 919 |
| `synonym_rule` | 684 |
| **Total** | **29,586** |

Applied synonym rules (each preserves concept semantics for every code it can touch):

| Rule | Justification |
| --- | --- |
| `u ác tính` → `ung thư` | malignant neoplasm / cancer, equivalent register |
| `u ác tính` → `bướu ác tính` | regional Vietnamese variant |
| `ung thư` → `u ác tính` | reverse pair |
| `u lành` → `u lành tính` | benign neoplasm, expanded form |

Rejected and recorded so the exclusion is auditable: `viêm phổi ↔ viêm phế quản phổi`
(bronchopneumonia is a distinct entity), `bệnh ↔ hội chứng`, `cấp ↔ mạn` (acuity is coded).

An alias is never derived from a damaged title — C20's `Bao gồm: Bóng` yields **zero**
aliases, so repair cannot make corrupted text more reachable. No alias comes from
public-test text, and the Audit-0067 AI consensus was used only to decide where to look,
never as authority for a mapping.

## 7. Acceptance Gate — not passed

| Requirement | Result |
| --- | --- |
| Materially fewer coverage failures | **PASS** — non-empty 78→86%, probe 1/16→9/16 |
| No increase in catastrophic lexical false friends | PASS — B05 now carries `Bệnh sởi`, so the `sởi`/`sỏi` collision has a correct competitor |
| **No regression on clean exact-alias cases** | **FAIL** — consensus-selected @1 fell 5→3, @10 fell 8→7, one record lost its candidates |
| Deterministic repeat | PASS |
| No change to E1/E2/E3/assertion outputs | PASS by construction — only the ICD KB changed |

**Diagnosis of the regression.** Candidate sets grew 9.0 → 11.5. Adding 29,586 aliases —
half of them accent-stripped variants — created more competitors for rank 1 without a
matching precision signal. The unaccented channel is the likely culprit: it was added as a
secondary channel but the linker's scoring does not yet privilege the accent-sensitive
exact channel over it, so a diacritic-insensitive match can outrank a diacritic-exact one.
That is the same failure mode as `sởi`/`sỏi`, now arriving from the alias side.

n = 8 is small and these are weak labels, so this is a signal rather than a measurement —
but the gate is written to refuse exactly this trade, and it refuses.

## 11. Remaining Risks and Next Step

1. **Ranking regression must be fixed before v4 ships.** The concrete change is to restore
   exact-channel priority: score an accent-sensitive exact/alias hit strictly above an
   accent-stripped one, so the added aliases raise recall without diluting rank 1.
2. **Recovery is 24.2%.** 2,104 concepts remain damaged, mostly title wrapping across
   `pdftotext` layout lines. A line-joining pass before column splitting is the obvious next
   improvement and would likely lift recovery substantially.
3. **Alias breadth is modest** — 684 synonym-rule aliases from four reviewed rules. The rule
   table should grow under review, not by generation.
4. **`I10` (essential hypertension) is genuinely absent from the index**, so no repair can
   surface it. That is a KB-content gap, not a retrieval gap.
5. **Weak labels, small n.** The @1 comparison rests on 8 records of AI consensus.

## 12. Next-Milestone Handoff (§14)

`PRETRAINED_SEMANTIC_RETRIEVER_ON_REPAIRED_KB` remains the right next step, but it should
run against a v4 that has passed the ranking gate — training a retriever against text that
is 13.7% still-damaged would bake that damage into the weights. Sequence: fix exact-channel
priority, extend title recovery with line joining, re-run this regression, then select the
retriever. The 9B deployed-parameter budget is the hard constraint; the owner's RTX 4060 is
not — Colab/A100/H100 are available for that training.

## 13. Verdict

**`ICD_KB_V4_ACCEPTED_OFFLINE_ONLY`**

The governed source proved sufficient and the corruption was diagnosed precisely: a
column-selection defect that captured ICD instruction notes instead of Vietnamese titles.
673 titles were recovered deterministically from local evidence and a 29,586-entry alias
layer was built where none existed. Coverage improved materially — 1/16 to 9/16 on the
probe — but top-1 ranking regressed, so v4 is retained for further offline work and is
**not** promoted to the leaderboard.
